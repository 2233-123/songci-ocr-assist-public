## 1. 背景与目标

《无悔华夏》的「择律」玩法会给出一句词的首句，以及 3 个词牌选项，玩家要选出与词句匹配的词牌。

本项目做一个**安卓悬浮窗提示器**：读屏 → OCR 识别首句 → 查表得到词牌 → 在正确选项气泡上画框。

### 1.1 目标（MVP）

* 只在**「（首句）」**这一种模式工作
* 只做一件事：**高亮正确词牌**
* **全离线**（识别与匹配都在端上，不联网）
* 由 CI 产出可分发的 APK

### 1.2 非目标（明确不做）

* ❌ 不自动点击、不注入、不读写游戏进程内存
* ❌ 不做词句信息卡、不做策略建议
* ❌ 不覆盖「只给提示语 / 上句 / 下句 / 全词」等其它模式（架构留扩展点，不实现）
* ❌ 不做 iOS、不做模拟器 PC 版

## 2. 关键预研结论（已在词句库上验证）

词句库 = 游戏 `SongCiVerseConfig` 的 99 条词句（导入时剔除 2 条"需特殊名臣解锁"的条目，
它们归属未收录词人、且政策为空壳，无任何可实现内容）。索引已生成并校验通过：
`app/src/main/assets/verses.json`（99 条 / 40 个词牌 / 19.9 KB）。

| 检查项 | 结果 |
|---|---|
| 99 条词句取**首句**是否有重复 | **无重复**（首句 5~42 字，平均 13.2 字） |
| OCR 完全正确时精确查表 | **99/99 命中** |
| ~~每首句随机注入 1/2/3 个字错 → 最近邻 100%~~ | ~~100%~~ **✗ 此结论已被推翻，见下方「实施期更正」** |
| 提示语（`HintSpeechList`）唯一性 | 751 条提示语仅 574 条唯一，**87 条会对应多条词句** |

**结论**：
1. **首句**是可靠匹配键 → 精确查表 + 最近邻兜底两层足够；
2. 提示语**不是**可靠匹配键（歧义多），MVP 不采用；
3. 用户提供的实机截图中，「明月别枝惊鹊」→ 词句 id 75 → 词牌 **西江月**，正是三个选项之一 ✓ 方案在真实截图上成立。

> **相似度定义（两端必须一致）**：`sim(a,b) = 1 − Levenshtein(a,b) / max(len(a), len(b))`，
> 输入为去掉中文标点与空白后的首句。
> 预研脚本最初用 `difflib.SequenceMatcher.ratio()`（Ratcliff-Obershelp），与上式**不完全等价**，
> 因此移植前必须用上式在 Python 侧复测一遍（预期仍为 100%），Kotlin 侧实现同一公式。
> 阈值 **0.72** 也以该式为准。
>
> ### ⚠️ 实施期更正（2026-10-05，已按上式复测）
>
> 上表 **2/3 个错字** 那两行是 `difflib` + 另一种错字模型的结论，按本节规定的
> 归一化编辑距离复测**不成立**：
>
> | 注入错字数 | 提示但判错词牌 | 提示覆盖率 | 不提示（安全失败） |
> |---|---|---|---|
> | 1（1980 例） | 0 | 100% | 0 |
> | 2（495 例） | 0 | 98.6% | 1.4%（3 条 5~6 字短句） |
> | 3（198 例） | 0 | 86.9% | 13.1%（16 条短句） |
>
> 关键结论**不变且更强**：任何错字量下都**没有出现"画框但画错"**（阈值 0.55~0.85 扫描，
> 误报恒为 0.00%）；2/3 个随机整字替换只会让短首句的结果**不提示**。
> 因此 §1.2「宁可不提示，也不误报」与 §9.3「误报 0」成立；而「命中 ≥95%」在 3 错字下
> 需要用 `Config.SIMILARITY_THRESHOLD` 换（0.65 → 97.0%，0.60 → 98.7%，实测仍 0 误报）。
> 复算：`python tools/tune_matcher.py`（与 Kotlin 侧同式）。


## 3. 架构与组件

工程根目录（`E:\Desktop\宋词辅助`）：

```
├── data/                             # 游戏导出的配置（**不入库**，属游戏素材；见 data/README.md）
│   ├── README.md                     #   格式说明与"如何自备数据"
│   ├── *.example.json                #   仅结构骨架（入库）
│   └── SongCiVerseConfig.json        #   自备：词句库
│   └── SongCiPoetConfig.json         #   自备：词人表
├── tools/gen_verse_index.py          # 生成 + 校验 verses.json（纯 Python，无数据库依赖）
├── docs/specs/                       # 设计文档 / 后续实施计划
└── app/src/main/
    ├── AndroidManifest.xml           # 悬浮窗 / 录屏 / 前台服务 / 通知
    ├── assets/verses.json            # 词句索引（已生成并提交）
    └── java/com/songci/assist/
        ├── MainActivity.kt        # 引导页：三项授权 + 开始/停止 + 状态
        ├── CaptureService.kt      # 前台服务：MediaProjection → ImageReader 取帧
        ├── FramePipeline.kt       # 节流(2fps) + 缩放到宽≤1080 + 两段式裁剪调度
        ├── OcrEngine.kt           # ML Kit 中文识别（内置模型，离线）→ 文本块+包围盒
        ├── VerseIndex.kt          # assets 载入 + 首句规范化 + 精确查表
        ├── Matcher.kt             # 最近邻兜底 + 挑"首句行 / 选项气泡"（纯函数）
        ├── OverlayView.kt         # 绘制：高亮框 + 箭头 + 顶部状态条 + 悬浮球
        └── OverlayService.kt      # 悬浮窗生命周期（TYPE_APPLICATION_OVERLAY）
```

### 3.1 职责边界

| 组件 | 做什么 | 不做什么 |
|---|---|---|
| `CaptureService` | 持有 MediaProjection，产出一帧 `Bitmap` | 不认识文字 |
| `FramePipeline` | 决定"什么时候取帧、取哪块" | 不做识别、不做匹配 |
| `OcrEngine` | `Bitmap → List<TextBlock>`（文本 + 包围盒） | 不理解语义 |
| `VerseIndex` | 载入索引、规范化首句、精确查表 | 不碰屏幕 |
| `Matcher` | `List<TextBlock> → HighlightTarget?`（纯函数，可单测） | 不绘制、不取帧 |
| `OverlayView` | 画框/状态条 | 不判断对错 |

`Matcher` 是**纯函数**：输入文本块列表（含坐标），输出"高亮哪个框 + 顶部文案"，因此可以在 JVM 单测里用假数据完整覆盖。

## 4. 数据流

```
MediaProjection ──► ImageReader ──► 最新帧（2 fps，缩放到宽 ≤1080）
                                      │
                    ┌─────────────────┴──────────────────┐
                    │ 第一段：只 OCR 顶部                 │  先跑，成本低
                    │  裁切区 y ∈ [0, 0.45H]              │
                    │  → 文本块与 99 条首句逐个算相似度      │
                    │  → 最高相似度 ≥ 0.72 且长度 ≥ 5 视为命中│
                    └─────────────────┬──────────────────┘
                                      │ 命中 → 词牌 P
                    ┌─────────────────┴──────────────────┐
                    │ 第二段：只 OCR 中部                 │
                    │  裁切区 y ∈ [0.30H, 0.80H]          │
                    │  → 找文本 == P 的块（词牌名候选 40 个）│
                    │  → 其包围盒 = 要画框的选项气泡         │
                    └─────────────────┬──────────────────┘
                                      ▼
                        OverlayView：气泡画框 + 顶部状态条
```

### 4.1 关键决策

* **不依赖"（首句）"三个字的位置** → 分辨率、字号、UI 微调都不影响；将来加模式只需换匹配键。
* **首句被 OCR 拆成两行**时，先把顶部相邻行按 y 坐标拼接再匹配。
* **两段式**而非整屏 OCR：通常只跑第一段；只有命中首句时才跑第二段，省电省时。
* **未命中不显示任何东西**（宁可不提示，也不误报）。
* **第二段找不到词牌气泡**（OCR 漏识）→ 顶部状态条显示「应选：西江月」，不画框。
* 相似度用 §2 定义的**归一化编辑距离**（两端同式）；阈值 0.72、裁切区（顶部 `[0,0.45H]`、
  中部 `[0.30H,0.80H]`）都写进 `Config.kt`，可调，真机调参后固化。

## 5. 悬浮窗交互

```
┌──────────────────────────────────────────┐
│  ╭──────────────────────────────╮        │  ← 顶部状态条(半透明黑底)
│  │ 明月别枝惊鹊 → 西江月  ✓0.98 │        │     "首句 → 词牌 置信度"
│  ╰──────────────────────────────╯        │
│              ╭─ 正确气泡 ─╮               │  ← 圆角矩形描边(亮青绿 6dp)
│              │  西江月    │◄──┐           │     + 左侧小三角箭头
│              ╰────────────╯   │           │
│                            ╭─╮            │  ← 右下悬浮球(可拖动)
│                            │词│            │     单击=暂停/继续, 长按=退出
│                            ╰─╯            │
└──────────────────────────────────────────┘
```

* **两个独立 window**：高亮层 `FLAG_NOT_TOUCHABLE`（完全不挡操作）+ 悬浮球可触摸（`FLAG_NOT_FOCUSABLE`）。合在一个 window 里会导致悬浮球也点不动。
* 命中消失后**立即清除**高亮；连续 1.5 s 无命中（例如已经选完）淡出。
* 顶部状态条可在偏好里关掉，只留高亮框。
* 悬浮球位置持久化；靠近边缘时自动吸附。

## 6. 权限 / 版本基线 / 异常处理

### 6.1 权限

| 权限 | 时机 | 说明 |
|---|---|---|
| `SYSTEM_ALERT_WINDOW` | 首次启动 | 跳 `ACTION_MANAGE_OVERLAY_PERMISSION` |
| 屏幕录制（MediaProjection） | **每次**启动服务 | 系统弹窗确认；由前台服务持有，整局有效 |
| `POST_NOTIFICATIONS`（13+） | 首次启动 | 前台服务常驻通知（内含"停止"按钮） |
| `FOREGROUND_SERVICE` + `FOREGROUND_SERVICE_MEDIA_PROJECTION` | 声明 | Android 14 起强制要求 |
| 忽略电池优化 | 提示不强制 | 否则长时间后台会被系统掐断 |

* **版本基线**：`minSdk 26`（Android 8）/ `targetSdk 34`
* **目标设备是 Android 16（API 36）**：`targetSdk 34` 的 APK 在 Android 16 上以**兼容模式**运行，
  API 36 针对 targetSdk≥36 的新限制不适用；等真机跑通后再评估是否上调 `targetSdk`（35/36 会引入
  edge-to-edge 等额外适配，与本功能无关）。**此点标记为待真机验证**。
* 官方文档网络不可达时不得凭记忆断言新版本行为，一律以真机实测为准。
* Android 14+ 强制"**每次会话重新授权** + 必须由前台服务持有 + 必须注册 `MediaProjection.Callback`"，本设计天然满足（见 [Media projection](https://developer.android.com/media/grow/media-projection)）

### 6.2 异常路径（都要有可读提示，不静默失败）

| 情况 | 行为 |
|---|---|
| 悬浮窗 / 录屏未授权 | 引导页标红 + 一键跳设置；不启动服务 |
| 用户在系统通知里停止投屏 | `MediaProjection.Callback.onStop` → 通知变"已停止，点此重新开始" |
| 本帧 OCR 全空 / 无有效文本 | 跳过本帧，不绘制 |
| 最高相似度 < 0.72 | 不显示 |
| 命中词牌但屏上找不到气泡 | 顶部状态条「应选：X」 |
| 同名词牌出现多次（如提示文案里也有） | 取**面积最大且在屏幕中部区域**的块 |
| 旋转 / 分辨率 / 刘海变化 | 每帧用当帧尺寸，不缓存坐标 |
| 电池优化导致服务被杀 | 常驻通知可一键重启；文档给厂商白名单指引 |

## 7. 性能与耗电

> ⚠️ **本节多处与实现不符**（实现期更正）：
> `只 OCR 裁剪区域` 与 `省电模式 1 fps` 均未采用。实际做法是
> **原生分辨率识别 + 只处理最新帧 + 首遍裁掉底部 15% + 二次识别限流 3 秒**。
> 原因是 ML Kit 中文模型单次识别 1.6~2.4 秒，瓶颈在「识别面积与次数」而非取帧频率。

* 取帧 **2 fps**（`Config.MIN_FRAME_INTERVAL_MS = 500`）
* 未命中连续 **30 帧** → 进省电模式
* 命中后 3 秒内不重复跑第二段（同一局结果不变）
* 目标：连续 30 min 使用不明显发热；具体指标在真机回归里记录

## 8. 数据资产：`verses.json`

由**本工程自带**的 `tools/gen_verse_index.py` 生成（纯 Python 标准库，**不依赖数据库**）：

```bash
python tools/gen_verse_index.py          # 生成 + 校验
python tools/gen_verse_index.py --check  # 只校验已生成的文件
```

数据源：`data/SongCiVerseConfig.json`（+ `data/SongCiPoetConfig.json` 补词人姓名）；
生成时必须**剔除 `UnlockNeedMinister ∩ {999}` 的词句**（实测 ID 9、87），与词句库口径一致。

```json
{
  "generated_at": "2026-10-05",
  "source": "SongCiVerseConfig.json (剔除需特殊名臣解锁的词句)",
  "count": 99,
  "pai_list": ["西江月", "念奴娇", "..."],
  "verses": [
    {"id": 75, "name": "明月别枝惊鹊", "head": "明月别枝惊鹊清风半夜鸣蝉",
     "pai": "西江月", "style": 2, "poet": "辛弃疾", "poet_ids": [2]}
  ]
}
```

* `head`：首句（正文到第一个断句符）去掉**全部标点与空白**后的字符串 = 匹配键
* `style`：1=豪放 / 2=婉约（MVP 不用，留给扩展）
* 校验规则（任一不过即失败并返回非 0）：条数一致、`head` 唯一且长度 ≥ 5、`id` 唯一、
  词牌非空、风格 ∈ {1,2}、不含 9/87
* **已生成的 `app/src/main/assets/verses.json` 随仓库提交**（App 运行必需，离线查表用）；
  文件仅约 20 KB（99 条短句，**不含词句全文**，只有首句 + 词牌 + 词人姓名）
* **游戏原始配置不入库**：`data/SongCiVerseConfig.json` / `data/SongCiPoetConfig.json`
  属于游戏素材，已 gitignore。CI 因此**无法重新生成索引**，只能校验已提交索引的一致性
  （`check_index_committed.py`）；索引**内容**的合法性改由 JVM 测试
  `CommittedIndexTest` 守护（条数、唯一性、字段、可自查、词牌集合的模糊匹配安全前提）。
  要重新生成索引，需自行从设备导出数据（见 `data/README.md`）

|---|---|

| `MatcherNoiseTest` | 每条首句注入 1/2/3 个错字 → 断言最近邻仍命中正确词牌 |
| `MatcherEdgeTest` | 首句被拆两行；词牌不在屏（输出「应选 X」）；纯数字/噪声不误报 |

### 9.2 Python 侧

* `gen_verse_index.py` 生成 + 校验（见 §8）
* 匹配算法先在 Python 里调参（阈值、规范化规则），再原样移植到 Kotlin

### 9.3 真机手测清单（写进 README，逐项打勾）

1. 安装 → 三项授权 → 悬浮球出现
2. 进游戏择律页：首句出现后 **≤1 s** 出框，框在正确气泡上
3. 连续 **20 局**统计命中率 / 误报率（目标：误报 0，命中 ≥ 95%）
4. 选完后框自动消失，不残留
5. 连续 30 min：耗电、温度、是否被系统杀
6. 息屏 / 切后台 / 旋转后恢复正常
7. 停止投屏后再启动，能恢复工作

* 正式分发需要**固定签名**：本地 `keytool` 生成 keystore → base64 存 GitHub Secrets
  （`KEYSTORE_BASE64` / `KEYSTORE_PASSWORD` / `KEY_ALIAS` / `KEY_PASSWORD`）→ CI 解码后签名
* ⚠️ **keystore 必须备份**：丢失后无法覆盖升级，用户只能卸载重装
* 发布用 **GitHub Release**（已开元，Release 附件公开可下载）
* **不做第三方加固**：加固会改写 DEX、hook 反射与 Binder，而本 App 的关键能力
  （MediaProjection 录屏、`TYPE_APPLICATION_OVERLAY` 悬浮窗、ML Kit 的 native OCR 管道）
  恰好都依赖这些机制，加固后需逐项真机复测，收益（提高逆向门槛）与风险不成正比。
  分发形态就是「CI 出已签名 release 包 → GitHub Release 附件下载」，用户需允许安装未知来源应用。
